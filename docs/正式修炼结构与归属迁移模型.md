# 正式修炼结构与归属迁移模型

## 1. 目标

本文档定档门派、功法、章节、单元和知识点的正式身份、当前归属、历史归属与迁移规则。前端可以调整页面结构和交互，但不得绕过这里定义的关系直接从名称或 id 文本推断归属。

## 2. 稳定身份与直接归属

所有实体 id 只表示“它是谁”，创建后不因改名、排序或迁移而变化。旧静态 id 保持原样，新建正式实体使用不包含父级和名称的稳定 id。

```text
Sect.id
  -> Technique.sectId
       -> TechniqueChapter.techniqueId
            -> TechniqueUnit.chapterId
                 -> KnowledgePoint.unitId
```

每个实体同时只有一个当前直接父级，因此当前归属不创建单独的关系 id。名称允许重复；不同功法分别创建的同名知识点是不同实体。

```text
移动：保留实体 id，只修改直接父级。
复制：创建新实体和新 id。
归档：保留旧 id 和历史关联，不复用 id。
```

## 3. 独立知识与秘术合集

`system_standalone` 是隐藏的系统归属，不在普通门派列表显示。它同时承载两类不同内容：

```text
独立知识
  -> 正式 Technique（isSystem = false）
       -> 章节 -> 单元 -> 知识点

秘术合集
  -> standalone_knowledge（isSystem = true）
       -> chapter_standalone_inbox
            -> unit_standalone_inbox
                 -> 零散知识点
```

独立功法仍是正式功法，只是 `sectId` 指向 `system_standalone`。它拥有完整功法结构，可以整体迁入普通门派；普通门派中的功法也可以整体迁入独立知识。秘术合集则使用固定隐藏容器，避免零散知识点处理空外键：

```text
system_standalone
  -> standalone_knowledge
       -> chapter_standalone_inbox
            -> unit_standalone_inbox
```

系统门派和系统功法不出现在普通门派与功法列表。AI 新功法可以选择“独立知识（无门派归属）”作为目标；生成的正式功法仍使用普通 `Technique` 身份。秘术知识点参与个人统计和知识点复习，但系统功法不参与普通功法层数与突破。

前端通过 `/cultivation/independent` 访问独立功法列表，通过 `/cultivation/secret-arts` 直接访问秘术知识点。两个入口都与普通门派同级，但不会把 `system_standalone` 暴露成普通门派。

## 4. 正式结构仓库

`CultivationStructureRepository` 是正式修炼结构的统一存储边界：

```text
schemaVersion
sects[]
techniques[]
chapters[]
units[]
knowledgePoints[]
ownershipChanges[]
importMappings[]
updatedAt
```

仓库保存当前结构、迁移历史和 AI 导入映射。修炼记录不进入该仓库，继续作为独立历史账本保存。加载仓库时补齐新的系统默认实体；结构损坏时回退到默认正式结构。

## 5. 功法迁移

功法迁移是主要归属调整流程。迁移只修改 `Technique.sectId`。章节、单元和知识点通过直接外键链自动跟随，所有 id 保持不变。系统功法不能迁移；普通功法可以在可见门派与专用的 `system_standalone` 独立知识归属之间迁移，但不能迁入其他系统门派。

迁移预览需要统计：

- 调整前和调整后的门派。
- 随功法迁移的章节、单元和知识点数量。
- 有效和已软删除的历史修炼记录数量。
- 功法修炼默认规则和层数规则数量。
- 仍以该功法为合并目标的活动 AI 草案数量。

执行成功后，更新功法并追加一条 `OwnershipChangeRecord`。旧 URL 根据稳定 `techniqueId` 重定向到功法当前门派下的新 URL。

## 6. 知识点迁移

知识点迁移只修改 `KnowledgePoint.unitId`。支持同功法内调整、秘术知识点转入正式功法、功法知识点转入秘术合集以及明确确认的跨功法迁移。

迁移保留知识点 id、修炼记录、复习历史和手动复习间隔；未手动覆盖的规则改为继承目标功法规则。跨正式功法的“复制”不是迁移，必须创建新知识点 id。迁移预览需要提示旧功法和新功法覆盖率都会重新派生。

## 7. 当前统计与历史统计

修炼记录保存发生当时的 `sectId` 和 `techniqueId` 快照，不因迁移回写。

```text
当前归属统计：按 Technique 当前 sectId 汇总。
历史来源统计：按 PracticeRecord.sectId 快照汇总。
```

个人总计和知识点修炼分摊不因统计口径变化。前端必须明确标注当前结构视图和历史来源视图，不能用一个门派数字同时表达两种含义。

## 8. AI 导入映射

AI 草案在预览阶段只生成建议正式 id，不保存正式映射。只有导入计划完成原子写入并进入 `applied` 状态后，才能创建 `TechniqueImportMappingRecord`。

映射记录保存项目、草案版本、正式功法以及各草案实体到正式实体的 id 对应关系。后续重新导入依赖映射更新原对象，不能只根据名称自动合并。

## 9. 前端稳定接口

- 列表和详情读取 `CultivationStructureRepository`。
- 层级查询使用 `knowledgeOwnership`，不解析 id 文本。
- 迁移前调用 preview 函数，确认后调用 apply 函数并一次性保存仓库。
- 普通编辑只修改实体字段；调整归属使用独立入口。
- 旧 URL 通过稳定实体 id 跳转到当前规范路径。
- 界面统一提供删除与恢复；删除底层写入 `archivedAt`，复制明确生成新 id。

## 10. 当前实现边界

当前已经实现正式仓库加载与保存、隐藏独立知识归属与秘术合集容器、归属解析、功法和知识点迁移预览、迁移应用、归属变更记录、当前/历史两套统计函数、AI 导入映射合同、旧功法 URL 重定向逻辑，以及正式知识点编辑、软删除与恢复数据函数。

应用顶层已经加载并保存正式仓库，修炼页、门派页、功法页、知识点页、进度计算和复习提醒已经读取仓库及其动态归属索引。独立知识页展示系统归属下的正式独立功法；秘术合集页支持创建正式零散知识点，新实体自动归入秘术收集箱并由仓库持久化。知识点迁移界面已经支持目标选择、影响预览和确认执行，迁移后当前页面会移除失效的修炼选择。整门功法迁移界面也已经接入，支持普通门派与独立知识之间双向迁移；确认后下级结构自动跟随，当前归属统计重新汇总，旧 URL 跳转到当前规范路径。AI 导入确认已经可以一次性写入正式仓库和导入映射；正式知识点编辑、删除和恢复页面已经接通：删除带二次确认并写入 `archivedAt`，恢复会清除该字段，当前结构查询、修炼选择、进度和提醒均排除已删除项，实体 id 与历史数据保持不变。正式章节和单元的人工编辑、排序、归档/恢复仍待补。事件、游历和部分 AI 表单选择器仍读取默认静态实体。
