# 个人修炼状态系统需求说明

## 1. 产品定位

本系统是一个本地 Web 应用，用游戏化方式管理个人学习进度、考试事件、项目任务和审美积累。

核心目标：

```text
把学习任务变成可记录、可计算、可调整、可复盘的个人修炼系统。
```

系统不强制用户按照固定培养方案学习。用户可以自由选择门派、功法和知识点进行修炼。功法之间可以设置推荐前置关系，但前置关系只用于提示，不作为硬性锁定。

## 2. 核心结构

系统主结构：

```text
门派 -> 功法 -> 知识点 -> 修炼记录 -> 数值成长 -> 境界突破
```

辅助结构：

```text
事件 -> 期末考试、课程设计、突破考试、长期项目
游历 -> 阅读、电影、番剧、游戏剧情等审美积累
AI 草案 -> 根据教材、考纲、目标生成可编辑修炼计划
```

## 2.1 界面层级设计

第一版界面采用层级式结构，而不是把所有功能平铺在同一级页面中。

页面层级：

```text
界面 1：首页 / 个人总览
  -> 界面 2-1：事件界面
  -> 界面 2-2：游历界面
  -> 界面 2-3：修炼界面
       -> 界面 3：功法界面
            -> 界面 4：知识点修炼界面
```

首页负责显示个人当前总体状态：

```text
境界
法力
神识
神魂
事件入口
游历入口
修炼入口
```

事件界面负责显示事件记录，并提供安排新事件的入口。

游历界面负责显示游历记录，并提供记录新游历的入口。

修炼界面负责选择和创建门派。用户选择某个门派后，进入该门派的功法界面。

功法界面负责显示当前门派提供的法力、神识等信息，并展示该门派下的功法列表。用户选择某个功法后，进入该功法所属的知识点修炼界面。

知识点修炼界面是修炼系统的核心界面。知识点需要按照章节和知识点层级组织，并且明确属于当前选中的功法，视觉上接近文件夹树：

```text
门派
  功法
    章节
      知识点
```

用户点击某个知识点时，系统弹出该知识点的详情信息，并允许在该知识点下记录修炼。

知识点修炼界面还需要提供一个独立的“修炼”入口。该入口用于记录一次综合修炼，用户可以在记录中选择本次涉及到的多个知识点。系统后续需要把综合修炼记录同步到所有相关知识点的进度里。

后续可视化方向：

```text
第一阶段：文件夹式知识点树状列表
第二阶段：图形化知识树
```

图形化知识树中，已经修炼过的知识点可以点亮，未修炼或薄弱知识点保持较暗状态，用于直观看到当前修炼版图。

## 3. 核心对象

门派是学习领域。

第一版默认门派：

```text
数学
哲学
英语
```

系统必须支持用户自定义新增门派。

门派需要记录：

```text

门派总神识
```

## 3.3 知识点

知识点是功法下面的最小修炼单元。

知识点由用户手动创建，或由 AI 生成草案后确认导入。

知识点需要记录：

```text
知识点 id
所属门派
所属功法
所属章节，可选
知识点名称
知识点描述
知识点精细度：粗略、普通、细分
基础价值
难度
重要度
所属层级目标
可修炼最高层级
练习要求数量
笔记要求数量
思考要求数量
复习状态和当前阶段
最近复习时间和下次复习时间
知识点自定义复习间隔，可选
法力/神识收益分配
完成状态
当前修炼层级
最后修炼时间
退化状态
```

知识点 id 是程序识别知识点的唯一标识。知识点名称可以重复，id 不能重复。系统不能依赖知识点名称判断是否为同一个知识点，只能依赖 id 判断。

知识点 id 采用固定格式：

```text
kp_{门派代码}_{功法代码}_{章节代码}_{关键词代码}_{三位序号}
```

各部分含义：

```text
kp：知识点固定前缀。
门派代码：sectCode，例如 math、phil、eng。
功法代码：techniqueCode，例如 analysis、western、reading。
章节代码：chapterCode，有明确章节时使用 ch01、ch02、ch03 等；无明确章节时统一使用 ch00。
关键词代码：keywordCode，用英文或拼音短码表示知识点关键词。
三位序号：serial，例如 001、002、003，用于区分同位置下的重复或近似知识点。
```

分隔和字符规则：

```text
不同部分之间使用下划线 _ 分隔。
关键词代码内部不使用下划线，多个词直接连写。
只使用小写英文字母、数字和下划线。
不使用中文、空格、标点、括号、斜杠。
```

示例：

```text
kp_math_analysis_ch01_limitdefinition_001
kp_math_analysis_ch00_function_001
kp_phil_western_ch04_descartes_001
kp_phil_descartes_ch00_meditation_001
kp_eng_reading_ch00_skimming_001
kp_eng_writing_ch00_argumentstructure_001
```

id 创建后原则上保持稳定。若知识点名称、章节或描述发生变化，优先修改对应字段，不轻易修改 id，避免已有修炼记录断开关联。

知识点的所有要求都必须可以手动调整。

AI 生成知识点时需要支持三种精细度：

```text
粗略：知识点数量较少，单个知识点价值较高。
普通：标准精细度，作为默认基准。
细分：知识点数量较多，单个知识点价值较低。
```

知识点可以按章节组织：

```text
功法 -> 章节 -> 知识点
```

章节划分默认由 AI 根据教材目录、考纲结构或知识体系生成。用户也可以选择不使用章节，将知识点直接放在功法下。

哲学知识点需要支持多视角拆分，不要求构建一个没有重复、无所不包的大一统体系。适合作为哲学知识点的单位包括：

```text
人物
概念
命题
论证
文本
比较关系
问题域
考试题
写作主题
```

哲学知识点可以额外记录：

```text
知识点类型：人物、概念、文本、论证、比较、问题域、题目、写作
加工视角：哲学史、原著精读、考试答题、专题研究、个人兴趣
核心问题
相关人物
相关文本
考试价值
研究价值
```

示例：

```text
笛卡尔方法论怀疑
笛卡尔如何建立现代主体哲学
笛卡尔与休谟的自我理论比较
笛卡尔主体与康德先验主体比较
“我思”是否证明实体性自我
```

这些内容可以同时存在，因为它们分别训练概念掌握、论证重构、比较能力、问题意识和写作能力。

英语知识点在系统中更接近能力点、技能点或训练点。示例：

```text
听力 -> 精听 -> 弱读连读识别
听力 -> 复述 -> 听后口头复述
阅读 -> 长难句 -> 定语从句嵌套识别
阅读 -> 篇章逻辑 -> 转折关系识别
写作 -> 段落组织 -> topic sentence + support
写作 -> 论证结构 -> concession and rebuttal
```

英语知识点可以额外记录：

```text
材料类型
难度级别
目标速度
目标正确率
目标字数
输出质量评分
复盘要求
```

## 3.4 修炼记录

修炼记录是用户每次学习行为的记录。

记录类型：

```text
练习
笔记
思考
测试
复习（巩固）
讲义写作
其他
```

第 9 步的第一版表单当前开放练习、笔记、思考、测试和复习五种类型。讲义写作和其他保留为后续扩展类型，暂不配置计算规则。

修炼记录需要记录：

```text
关联门派
关联功法
关联一个或多个知识点
各知识点的分配比例；分配数量由总数量乘以比例计算
记录标题
记录类型
数量
单位，例如题、条、篇、次、分钟
修炼耗时，单位分钟
正确率，可选，只作为质量和复盘证据
难度倍率，可选，测试时使用
复习结果，可选，复习时使用
备注
实际修炼时间
系统建议功法经验值
用户最终确认的功法经验值
获得法力
获得神识
获得神魂
收益来自功法默认值还是手动调整
手动调整原因，可选
软删除时间，可选
```

每条修炼记录只属于一门功法，可以关联该功法下的一个或多个知识点。综合修炼默认平均分配到所选知识点，用户可以在提交前手动调整分配比例。

测试记录增加功法经验值，但不直接增加知识点熟练度。测试后的订正、复盘、笔记和思考应分别记录为对应的修炼类型。

练习正确率不参与经验计算。即使结果错误，只要实际完成了方法、推导或计算流程，就按照练习数量获得经验；正确率只用于查看学习质量和安排后续复盘。

修炼记录采用软删除。已删除记录保留用于恢复和核对，但不参与经验值、知识点进度、功法、门派和个人属性统计。

当前实现状态：第 13 步境界和突破系统已经完成基础接入。用户可以提交单知识点或多知识点记录、调整分配比例、查看建议经验、手动修改最终经验并填写原因，也可以在记录列表中软删除和恢复记录。`src/utils/practiceStats.ts` 已经负责过滤软删除记录，并汇总个人、门派、功法和知识点的基础经验、法力、神识、神魂与记录数量；首页、修炼界面、功法界面和知识点修炼界面已经接入这些统计。`src/utils/practiceStorage.ts` 已经负责把修炼记录和记录-知识点关联分配保存到 localStorage，并在启动时读取；刷新页面后可以恢复已有修炼记录、记录列表和基础统计。`src/utils/practiceProgress.ts` 已经负责派生知识点维度进度、复习状态、功法层数、覆盖率、核心覆盖率、薄弱点比例和下一层缺口。`src/utils/realmProgress.ts` 已经负责从个人总修为、法力、神识和突破记录中派生当前境界、下一境界缺口和卡境状态；`src/utils/breakthroughStorage.ts` 已经负责把突破记录保存到 localStorage。当前本地保存覆盖修炼记录、记录-知识点关联和突破记录，默认门派、默认功法、默认知识点、默认层数规则和默认境界规则仍由静态数据文件提供。事件系统和突破事件绑定在第 14 步实现，界面视觉优化暂缓到第 18 步。

## 4. 属性系统

系统核心属性有三个：

```text
法力：练习、解题、执行、技术熟练度
神识：笔记、思考、推导、体系化理解
神魂：审美体验、阅读观影游戏后的总结感想、精神积累
```

属性来源：

```text
练习主要提升法力
笔记和思考主要提升神识
游历总结主要提升神魂
测试和课程项目同时提升法力与神识
讲义写作主要提升神识，也少量提升法力
```

个人总属性：

```text
总法力 = 所有学习修炼记录产生的法力总和
总神识 = 所有学习修炼记录产生的神识总和
总神魂 = 所有游历记录产生的神魂总和
```

门派属性：

```text
门派法力 = 该门派下所有功法产生的法力总和
门派神识 = 该门派下所有功法产生的神识总和
门派修为 = 门派法力 + 门派神识
```

## 5. 数值计算规则

当前实现状态：第 10 步已实现基础汇总层。系统先将 `deletedAt` 不存在的修炼记录作为有效记录，再汇总个人总经验、法力、神识、神魂；按 `sectId` 汇总门派统计；按 `techniqueId` 汇总功法统计；按 `PracticeRecordKnowledgePoint.allocationWeight` 将记录收益分摊到知识点。该实现已经通过浏览器交互验证：新增记录后个人、门派、功法和知识点统计同步变化；软删除后统计移除；恢复后统计恢复。

暂缓边界：当前基础汇总不等同于完整知识点进度。练习、笔记、思考和复习维度的封顶结算、测试不进入知识点熟练度、功法层数、境界突破、复习状态和退化规则继续按后续步骤实现。

## 5.1 知识点基础价值

每个知识点有一个基础价值，可由用户手动调整，也可由 AI 草案生成。

推荐计算思路：

```text
基础价值 = 基础点数 x (难度倍率 x 0.5 + 重要度倍率 x 0.5) x 层数倍率 x 补正系数
```

第一版可以先将基础价值作为直接可编辑字段，不必须强制使用公式。

基础点数需要考虑知识点精细度。默认设置：

```text
粗略知识点：150
普通知识点：100
细分知识点：50
```

以上数值只是默认值，用户可以在规则配置中调整。

数值编辑规则：

```text
AI 或系统默认给出功法总数值。
用户对知识点进行增减、合并、拆分或数值调整时，系统重新计算功法总数值。
功法总数值发生明显变化时，系统提示用户确认。
```

## 5.2 功法总值和补正系数

AI 生成某门功法规划时，需要先列出章节和知识点，再根据知识点基础价值、层数倍率和补正系数计算功法总值。

数学分析暂作为第一版数学门派的标准参考功法。和数学分析同档次难度、重要度的课程，修到第 6 层的总数值原则上应大致落在数学分析总数值的 50% 到 150% 范围内。

如果 AI 生成后的功法总值明显偏离参考范围，系统需要提示：

```text
当前知识点数量
当前功法总数值
参考功法总数值
偏离比例
建议补正系数
```

用户可以确认建议补正系数，也可以手动设置补正系数，允许功法总值超出参考范围。

## 5.3 任务最低经验要求与单次经验

每种修炼类型都有独立的最低经验要求。最低经验要求由知识点基础价值和当前功法的该类型要求比例计算。这里的比例不是对知识点价值进行分配，各类型比例不要求合计为 100%。

知识点完成所需任务数可以手动调整。调整任务总量后，单次任务经验自动变化，但该类型的最低经验要求不变。

公式：

```text
该类型最低经验要求 = 知识点基础价值 x 该类型要求比例
单次任务经验 = 该类型最低经验要求 / 该类型要求数量
本次该类型建议经验 = 本次实际数量 x 单次任务经验
```

示例：

```text
知识点基础价值：100
练习最低要求比例：70%
练习要求：20 题

最低练习经验要求 = 100 x 70% = 70
每完成 1 题经验 = 70 / 20 = 3.5
```

如果练习要求改为 40 题：

```text
最低练习经验要求仍为 70
每完成 1 题经验 = 70 / 40 = 1.75
```

练习正确率不乘入上述公式。正确率为 0 到 1 的可选记录值，只作为学习质量和复盘证据。

## 5.4 知识点进度结算

知识点进度直接按练习、笔记、思考和当前复习周期四个维度的经验结算。每个维度分别封顶，某个维度的超额经验不能补足其他维度。

```text
该维度结算经验 = min(该维度累计经验, 该维度最低经验要求)
该维度进度 = 该维度结算经验 / 该维度最低经验要求

知识点总进度 = 各维度结算经验之和 / 各维度最低经验要求之和
```

最低经验要求为 0 的维度不进入知识点总进度分母。测试不进入知识点进度。复习尚未到期时，复习维度不进入当前总进度分母；复习到期后，激活当前周期的复习要求。

超出最低要求的经验仍然计入功法经验，但不再增加知识点进度。知识点页面除显示大致总进度外，还必须分别显示练习、笔记、思考和当前复习周期已经完成多少、尚缺多少以及超出多少，避免总进度掩盖具体短板。历史复习经验不能提前抵扣未来复习周期。

## 5.5 任务类型默认规则与收益倾向

默认任务类型收益倾向：

```text
基础练习：法力 80%，神识 20%
进阶习题：法力 70%，神识 30%
证明推导：法力 45%，神识 55%
笔记整理：法力 25%，神识 75%
思考札记：法力 15%，神识 85%
体系总结：法力 30%，神识 70%
模拟考试：法力 75%，神识 25%
讲义写作：法力 40%，神识 60%
巩固复习：恢复退化为主，少量增加法力和神识
```

所有默认权重必须允许用户在设置中修改。
每门功法独立保存各任务类型的最低经验要求比例、法力权重和神识权重。修改一门功法的规则只影响该功法及其向上汇总的门派和个人数值。

每门功法还需要保存新知识点的默认练习、笔记和思考要求，以及默认复习间隔规则。创建知识点后默认使用所属功法的复习间隔，也允许知识点单独覆盖。测试不作为知识点熟练度要求。

测试类型的最低经验要求比例固定为 0。测试仍然增加功法经验，计算公式为：

```text
测试建议经验 = 题目数量 x 当前功法的每题基础经验 x 本次测试难度倍率
```

门派或学科可以提供每题基础经验的初始草案，但该值最终复制并保存在每门功法的独立规则中，允许手动修改。修改一门功法的测试基础经验不会影响其他功法。测试正确率不进入经验公式。

## 5.6 功法权重

功法本身也有法力/神识倾向。

最终收益倾向可由任务类型和功法倾向共同决定：

```text
最终法力比例 = 任务法力比例 x 0.6 + 功法法力比例 x 0.4
最终神识比例 = 1 - 最终法力比例
```

第一版可以采用该公式，也可以先用更简单的任务类型比例。公式必须集中在计算引擎中，方便以后修改。

## 5.7 功法规则修改范围

修改功法的基础值、最低经验要求比例、任务数量、测试每题基础经验或收益权重时，系统必须先展示影响范围和调整前后预览，再由用户选择历史记录处理方式：

```text
全部历史记录：默认记录和手动调整记录都按照新旧规则的变化比例修改。
仅默认记录：只重算使用功法默认值提交的记录，手动调整记录保持不变。
仅未来记录：历史记录全部保持不变，新规则只用于之后提交的记录。
```

一般调整比例为：

```text
调整倍率 = 新规则下的建议经验 / 旧规则下的建议经验
```

选择全部历史记录时：

```text
新最终经验 = 旧最终经验 x 调整倍率
```

例如某项基础值从 100 调整为 160，调整倍率为 1.6；选择全部历史记录时，默认值和手动调整值都乘以 1.6。选择仅默认记录时，手动调整值不变。

规则修改和重算只作用于当前功法及其关联知识点，然后更新所属门派和个人汇总，不扫描或修改其他功法。

## 6. 功法层数规则

每个功法默认 6 层。

功法层数和个人境界突破采用同构机制：

```text
经验达到门槛 -> 获得挑战下一层资格
知识点覆盖达标 -> 证明根基足够
完成突破要求 -> 层数真正提升
```

功法层数不能只看经验总量。每一层都需要同时检查：

```text
累计功法经验
知识点覆盖率
核心知识点覆盖率
薄弱知识点比例
突破要求
```

经验决定是否有资格突破，覆盖决定是否扎实，突破要求决定能否真正升层。

系统需要显示三类状态：

```text
经验不够：继续修炼
经验够但覆盖不足：补覆盖
经验和覆盖都达到：待突破
```

层数规则由 AI 默认生成，用户后续可以自定义校准。第一版默认层数规则包含：

```text
目标层数
累计经验门槛
知识点覆盖比例
核心知识点覆盖比例
允许薄弱点比例
突破要求清单
是否 AI 生成
是否用户已自定义
```

突破要求第一版先以文本清单展示，例如综合测试、阶段总结、结构图、讲义、口头讲解、稳定性检查等。后续事件系统和成果记录成熟后，再把这些文本要求绑定到具体事件、考试或输出记录。

## 7. 境界系统

个人境界分为 13 级。

境界提升条件：

```text
总法力达到门槛
总神识达到门槛
特殊等级完成突破任务
```

第 7 级和第 13 级为突破等级。

```text
第 7 级：中段突破等级，需要突破考试。
第 13 级：最终突破等级，需要突破考试。
```

境界门槛看个人总修为，不单独强制某个门派达到指定数值。用户可以通过数学、哲学、英语、游历以及自定义内容形成总体成长。具体突破任务可以带有学科倾向，例如数学考试、哲学考试、课程项目或综合输出，但数值门槛本身按个人总数值判断。

当前实现状态：第 13 步已经完成基础接入。系统通过 `src/data/defaultRealmRules.ts` 提供 13 级默认境界规则，通过 `src/utils/realmProgress.ts` 从个人统计和突破记录中派生当前境界、下一境界缺口和卡境状态，通过 `src/utils/breakthroughStorage.ts` 将突破记录保存到 localStorage。第一版总修为按总法力 + 总神识计算，每级还要求法力和神识分别达到该级总修为门槛的 25%。神魂当前仅在首页展示，暂不进入境界计算，等第 15 步游历系统完成后再校准。当前曲线保留第 7 级 1,149,120 和第 13 级 4,000,000 两个锚点，第 2-6 级按接近 2.58 倍的早期成长曲线重排，第 8-12 级按后期平稳阶梯衔接。

第一版暂定：

```text
第 7 级：个人总修为门槛暂定 1,149,120。
第 13 级：个人总修为门槛暂定 4,000,000。
```

境界卡点：

```text
如果法力和神识达到下一境界门槛，但突破任务未完成，则显示卡境状态。
卡境状态下数值可以继续累积，但境界不提升。
```

第 7 级和第 13 级需要存在对应 targetRealmLevel 且 status 为 completed 的突破记录。突破记录当前独立保存；和考试、课程项目、长期任务等事件记录的绑定留到第 14 步事件系统。

## 8. 毕业要求系统

毕业要求是独立于个人境界的目标系统。

```text
个人境界：主要看个人总修为和突破任务。
毕业要求：看指定学习阶段、专业、课程或项目要求是否达成。
```

因此，第 7 级不等同于本科毕业。第 7 级只表示个人总修为到达一个中段突破门槛；本科毕业要求需要通过独立目标、事件、考试或培养方案检查。

毕业要求可以包含：

```text
指定门派修为
指定功法层数
指定事件完成，例如期末考试、课程设计、毕业论文
指定考试成绩
指定项目成果
```

毕业要求可以作为事件、长期目标或成就存在，但不直接决定个人境界。

```text
用户可以自由选择任何门派、功法和知识点。
```

```text
泛函分析推荐前置：数学分析、实变函数、线性代数
```

## 10. 复习、退化和巩固系统

复习采用逐步扩大的阶段间隔，系统默认草案为：

```text
2 天 -> 7 天 -> 21 天 -> 60 天 -> 180 天 -> 365 天
```

该数组只是初始草案。每门功法可以独立修改复习阶段和间隔；单个知识点可以选择使用功法默认值，也可以保存自己的间隔覆盖。自定义间隔必须为大于 0 的整数、从小到大排列且不重复。完成最后阶段后继续重复最后一个间隔。

知识点复习状态：

```text
not_scheduled：尚未开始修炼，没有复习计划。
not_due：已安排复习，但还未到期。
due：已经进入当前复习窗口。
overdue：已经超过当前复习窗口。
```

第一次有效修炼后，知识点按照第一阶段生成下次复习时间。每个到期周期完成一次有效复习，并记录结果：

```text
forgotten：忘记，1 天后重试并退回第一阶段。
effortful：勉强想起，阶段不前进，下次间隔缩短为当前阶段的一半。
recalled：顺利想起，进入下一阶段。
```

功法默认宽限比例为 20%，允许在目标日期前后一定范围内完成，不要求精确在某一天复习。单个知识点建议复习 2 到 5 分钟，一次复习记录可以关联多个知识点。

修改功法复习间隔时，用户可以选择：

```text
仅未来周期：保留当前 nextReviewAt，完成下一次复习后使用新间隔。
全部重新安排：根据 lastReviewedAt、reviewStage 和新间隔重算相关知识点。
选择部分知识点：只重新安排用户选中的知识点。
```

知识点已有独立间隔覆盖时，默认不随功法规则修改，除非用户明确选择同时修改覆盖值。

## 17. 附录：数值实验

本节记录第一版数值系统的推导依据，属于默认参数来源，不是不可修改的硬规则。

## 17.1 数学分析基准实验

以刘玉琏版数学分析目录作为数学分析功法的参考基准。该目录上下册共约 636 个知识点，暂将这种划分视为普通精细度。

默认参数：

```text
普通知识点基础点数：100
难度倍率：1，范围 0 到 2
重要度倍率：2，范围 0 到 2
层数倍率：第 1 到 6 层暂定为 1、1.2、1.4、1.6、1.8、2
补正系数：1
```

知识点基础价值：

```text
100 x (1 x 0.5 + 2 x 0.5) x 1 = 150
```

假设第 1 层需要完成 400 个知识点：

```text
第 1 层最低修炼数值 = 150 x 400 = 60,000
```

假设第 2 层有 300 个知识点，层数倍率为 1.2：

```text
第 2 层单点价值 = 150 x 1.2 = 180
第 2 层最低修炼数值 = 180 x 300 = 54,000
```

假设第 3、4、5 层各有 300 个知识点，第 6 层有 100 个知识点，则数学分析修炼到第 6 层的最低总数值为：

```text
150 x 1 x 400
+ 150 x 1.2 x 300
+ 150 x 1.4 x 300
+ 150 x 1.6 x 300
+ 150 x 1.8 x 300
+ 150 x 2 x 100
= 360,000
```

## 17.2 AI 规划提示

AI 生成功法规划时，应先输出：

```text
章节列表
每章包含的知识点
每个知识点可修炼到的最高层级
每个知识点的难度、重要度、精细度
每个知识点各层级的任务要求
```

系统再根据规则计算各知识点数值、各章节数值和功法总值。

## 17.3 功法总值校准

数学分析第 6 层总数值暂定为 360,000。和数学分析同档次难度、重要度的课程，视内容多少，其第 6 层总数值原则上应在数学分析的 50% 到 150% 附近。

如果 AI 划分知识点后，某门功法总值明显偏离该范围，系统需要提示用户确认是否调整补正系数。

## 17.4 数学门派总值预估

以数学分析第 6 层总值 360,000 为基准，按各数学课程相对体量和难度做粗略系数估算：

```text
数学分析：1
高等代数：0.5
解析几何：0.7
```

## 17.5 数学功法任务量草案生成

数学功法以数学分析作为知识点任务量基准：

```text
练习：5 题
笔记：1 个
思考：2 次
基准法力/神识比例：0.55 / 0.45
```

系统使用课程价值系数和功法法力/神识倾向生成可编辑草案。课程价值系数只做温和缩放，避免高阶课程的单个知识点任务量线性膨胀：

```text
难度缩放 = clamp(sqrt(课程价值系数), 0.8, 1.25)

练习数 = clamp(round(5 x 难度缩放 x 当前功法法力权重 / 0.55), 2, 10)
笔记数 = clamp(round(1 x 难度缩放 x 当前功法神识权重 / 0.45), 1, 3)
思考数 = clamp(round(2 x 难度缩放 x 当前功法神识权重 / 0.45), 1, 5)
```

少量生成案例：

```text
数学分析：5 题、1 笔记、2 思考
高等代数：4 题、1 笔记、2 思考
运筹与优化：8 题、1 笔记、2 思考
抽象代数：4 题、2 笔记、3 思考
一般拓扑学：2 题、2 笔记、4 思考
微分流形：3 题、2 笔记、4 思考
```

该公式只生成任务数量草案，不直接计算经验。单次任务经验仍由知识点基础价值、最低经验要求比例和最终确认的任务数量计算。每个功法页面可以修改生成结果、重新生成草案或恢复初始草案。

哲学和英语使用相同生成机制，但需要分别提供适合本学科的基准任务组合，不直接套用数学题目基准。

每门数学功法生成一份独立的默认修炼规则对象。第一版系统草案如下：

```text
练习：最低经验要求比例 0.7；法力/神识比例读取当前功法配置
笔记：最低经验要求比例 0.2；法力/神识比例 0.2 / 0.8
思考：最低经验要求比例 0.2；法力/神识比例 0.3 / 0.7
测试：不增加知识点熟练进度；每题基础经验 = 30 x 课程价值系数
复习：最低经验要求比例 0.1；法力/神识比例 0.5 / 0.5
复习间隔：2、7、21、60、180、365 天；宽限比例 0.2
```

这些数值是系统生成的初始草案，不是锁死的最终标准。每门功法页面均可独立修改；修改某门功法的规则，不影响其他功法。测试的每题基础经验还可以根据学科、题目量和难度倍率手动调整。
