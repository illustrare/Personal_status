# 个人修炼状态系统需求说明

## 1. 产品定位

本系统是一个本地 Web 应用，用游戏化方式管理个人学习进度、考试事件、项目任务和审美积累。

核心目标：

```text
把学习任务变成可记录、可计算、可调整、可复盘的个人修炼系统。
```

系统不强制用户按照固定培养方案学习。用户可以自由选择门派、功法和知识点进行修炼。功法之间可以设置推荐前置关系，但前置关系只用于提示，不作为硬性锁定。

## 2. 核心结构

系统主结构：

```text
门派 -> 功法 -> 知识点 -> 修炼记录 -> 数值成长 -> 境界突破
```

辅助结构：

```text
事件 -> 期末考试、课程设计、突破考试、长期项目
游历 -> 阅读、电影、番剧、游戏剧情等审美积累
AI 草案 -> 根据教材、考纲、目标生成可编辑修炼计划
```

## 3. 核心对象

```text

```

## 4. 属性系统

系统核心属性有三个：

```text
法力：练习、解题、执行、技术熟练度
神识：笔记、思考、推导、体系化理解
神魂：审美体验、阅读观影游戏后的总结感想、精神积累
```

属性来源：

```text
练习主要提升法力
笔记和思考主要提升神识
游历总结主要提升神魂
测试和课程项目同时提升法力与神识
讲义写作主要提升神识，也少量提升法力
```

个人总属性：

```text
总法力 = 所有学习修炼记录产生的法力总和
总神识 = 所有学习修炼记录产生的神识总和
总神魂 = 所有游历记录产生的神魂总和
```

门派属性：

```text
门派法力 = 该门派下所有功法产生的法力总和
门派神识 = 该门派下所有功法产生的神识总和
门派修为 = 门派法力 + 门派神识
```

## 5. 数值计算规则

## 5.1 知识点基础价值

每个知识点有一个基础价值，可由用户手动调整，也可由 AI 草案生成。

推荐计算思路：

```text
基础价值 = 基础点数 x 难度倍率 x 重要度倍率 x 层数倍率
```

第一版可以先将基础价值作为直接可编辑字段，不必须强制使用公式。

## 5.2 任务点数分摊

知识点完成所需任务数可以手动调整。调整任务总量后，单次任务收益自动变化，但知识点总价值不变。

公式：

```text
单次任务点数 = 知识点基础价值 x 任务类型权重 / 该任务类型要求数量
```

示例：

```text
知识点基础价值：100
练习权重：70%
练习要求：20 题

每完成 1 题收益 = 100 x 70% / 20 = 3.5
```

如果练习要求改为 40 题：

```text
每完成 1 题收益 = 100 x 70% / 40 = 1.75
```

## 5.3 任务类型默认权重

默认任务类型收益倾向：

```text
基础练习：法力 80%，神识 20%
进阶习题：法力 70%，神识 30%
证明推导：法力 45%，神识 55%
笔记整理：法力 25%，神识 75%
思考札记：法力 15%，神识 85%
体系总结：法力 30%，神识 70%
模拟考试：法力 75%，神识 25%
讲义写作：法力 40%，神识 60%
巩固复习：恢复退化为主，少量增加法力和神识
```

所有默认权重必须允许用户在设置中修改。

## 5.4 功法权重

功法本身也有法力/神识倾向。

最终收益倾向可由任务类型和功法倾向共同决定：

```text
最终法力比例 = 任务法力比例 x 0.6 + 功法法力比例 x 0.4
最终神识比例 = 1 - 最终法力比例
```

第一版可以采用该公式，也可以先用更简单的任务类型比例。公式必须集中在计算引擎中，方便以后修改。

## 6. 功法层数规则

每个功法默认 6 层。

## 6.1 数学功法六层

```text
第 1 层：对课程有大概认知，基本理解每个知识点和作用，会做最基础的概念习题。
第 2 层：在第 1 层基础上，能对知识点进行推导理解，理清关系和动机。
第 3 层：在第 2 层基础上，会完成基本习题，掌握基本方法。
第 4 层：在第 3 层基础上，能自主写出概念体系与问题结构，说明各处关键和理解。
第 5 层：在第 4 层基础上，能完成进阶习题。
第 6 层：将以上内容融会贯通，达到能自己写一本讲义的程度。
```

## 6.2 哲学功法六层

```text
第 1 层：知道主要人物、概念、命题和问题背景，能完成基础名词解释。
第 2 层：能说清核心文本或观点的基本论证结构，知道概念从哪里来、针对什么问题。
第 3 层：能完成简答题，比较相近概念、人物和立场，避免混淆。
第 4 层：能整理某一哲学家、流派或问题域的完整框架，并说明内在张力。
第 5 层：能完成高质量论述题，进行跨人物、跨流派、跨时代比较。
第 6 层：能写出专题讲义或复习材料，形成自己的解释路径和问题意识。
```

## 6.3 英语功法六层

```text
第 1 层：能完成最基础材料，知道常见词汇、句型、题型或表达方式。
第 2 层：能分析句子、篇章、听力材料或作文结构，知道错误原因。
第 3 层：能完成常规练习，正确率、速度或输出质量达到基础要求。
第 4 层：能总结自己的方法体系，如阅读定位、听力复盘、写作模板与论证结构。
第 5 层：能处理难材料、限时任务、复杂表达或高分题型。
第 6 层：能稳定用于考试或真实表达，形成自己的语感、表达库和复盘系统。
```

## 7. 境界系统

个人境界分为 13 级。

境界提升条件：

```text
总法力达到门槛
总神识达到门槛
特殊等级完成突破任务
第 13 级额外满足数学门派修为条件
```

第 7 级和第 13 级为突破等级。

```text
第 7 级：对标本科毕业要求，需要突破考试。
第 13 级：对标本科完满要求，需要突破考试。
```

由于用户是数学专业，第 13 级突破额外要求：

```text
数学门派修为达到指定数值。
```

系统不强制用户修哪些数学功法，只检查数学门派总修为。数学分析、高等代数等课程可以作为自然前置建议，但不是硬性要求。

境界卡点：

```text
如果法力和神识达到下一境界门槛，但突破任务未完成，则显示卡境状态。
卡境状态下数值可以继续累积，但境界不提升。
```

## 8. 自由修炼和前置关系

系统遵循自由修炼原则：

```text
用户可以自由选择任何门派、功法和知识点。
系统不强制补基础课。
```

功法可以设置推荐前置：

```text
泛函分析推荐前置：数学分析、实变函数、线性代数
偏微分方程推荐前置：数学分析、常微分方程、实变函数、泛函分析
微分流形推荐前置：数学分析、解析几何、一般拓扑学
抽象代数推荐前置：高等代数、初等数论
数值分析推荐前置：数学分析、高等代数、常微分方程
```

前置不足时只提示：

```text
根基不足，理解风险较高或修炼效率可能下降。
```

不禁止用户继续修炼。

## 9. 退化和巩固系统

退化系统用于驱动复习。

基本规则：

```text
知识点长时间没有练习、测试或巩固时，当前熟练度下降。
历史根基不消失。
退化主要影响当前状态，不否定历史完成记录。
```

推荐状态：

```text
稳定
轻微退化
明显退化
生疏
```

巩固任务：

```text
完成代表题
复述定义或定理
整理错题
写复习笔记
完成小测
```

巩固效果：

```text
优先恢复退化熟练度。
恢复速度高于第一次学习积累。
可少量增加法力和神识。
```

## 11. 神魂系统

神魂代表审美、叙事、感受力和精神经验。

神魂主要来源：

```text
阅读
电影
番剧
游戏剧情
音乐
展览
戏剧
其他审美体验
```

神魂收益规则：

```text
神魂收益 = 作品基础值 x 完成度系数 x 输出系数 x 深度系数
```

第一版可以先简化为：

```text
完成度 + 感想字数 -> 神魂收益
```

神魂不作为 1-13 级主境界的硬门槛，但可以用于：

```text
角色面板展示
称号系统
审美积累统计
后续对哲学、英语写作等功法提供加成
```

## 12. AI 草案导入

AI 只生成草案，不直接修改正式数据。

用户输入：

```text
门派
功法
教材或考纲
目标层数
学习周期
补充要求
```

AI 输出：

```text
功法规划草案
知识点列表
每个知识点基础价值
每个知识点练习要求
每个知识点笔记要求
每个知识点思考要求
每个知识点测试要求
推荐前置
默认法力/神识比例
```

流程：

```text
输入课程信息
AI 生成 JSON 草案
前端展示草案
用户编辑草案
用户确认导入
草案转为正式知识点计划
```

草案状态：

```text
draft：待确认
approved：已导入
rejected：已放弃
```

## 14. 第一版 MVP 范围

第一版必须完成：

```text
本地 Web App
三大默认门派
默认功法目录
手动新增知识点
手动记录练习、笔记、思考、测试、巩固
```

```text

```

## 15. 需求原则

开发中必须遵守：

```text
规则集中在计算引擎，不散落在页面里。
AI 只生成草案，人确认后才生效。
用户可以自由修炼，系统只提示不强制。
所有关键数值都支持手动调整。
本地数据必须能保存和恢复。
先做可用闭环，再做复杂美化。
```
