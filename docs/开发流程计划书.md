# 个人修炼状态系统开发流程计划书

## 0. 项目目标

本项目要在本地开发一个 Web 应用，用游戏化数值系统管理个人学习、事件试炼和审美游历。

核心结构：

```text
门派 -> 功法 -> 知识点 -> 修炼记录 -> 数值成长 -> 境界突破
```

核心属性：

```text
法力：练习、解题、执行能力
神识：笔记、思考、体系化理解
神魂：阅读、电影、番剧、游戏剧情等审美体验后的总结积累
```

开发方式：

```text
一边学 Web 开发，一边完成项目。
每一步只解决一个明确问题。
每一步都要能运行、能看到结果、能记录进度。
```

## 第 7 步：做静态页面框架

目标：

```text
先把软件的主要层级页面摆出来，不处理复杂交互和真实数据保存。
```

要完成：

```text
界面 1：首页
- 显示个人境界、法力、神识、神魂
- 提供事件、游历、修炼三个核心入口

界面 2-1：事件界面
- 显示已有事件信息记录
- 提供安排新事件的入口

界面 2-2：游历界面
- 显示已有游历信息记录
- 提供记录新游历信息的入口

界面 2-3：修炼界面
- 显示门派列表
- 支持创建门派的入口
- 选择门派后，在当前页面显示该门派当前提供的法力、神识等信息
- 提供进入该门派知识点界面的入口

界面 3：知识点修炼界面
- 按功法和章节把知识点像文件夹一样层级排列
- 点击知识点后弹出知识点相关信息
- 支持从知识点详情中记录该知识点的修炼
- 支持直接点击修炼按钮记录一次综合修炼
- 综合修炼记录可以选择涉及到的多个知识点
- 综合修炼信息需要同步到相关知识点的进度里
```

需要学习的技术栈：

```text
React 组件
JSX
props
CSS 基础
页面布局
```

完成标准：

```text
首页、事件、游历、修炼、知识点层级界面都有基本内容，虽然数据可以先是假的。
页面结构能看出“个人总览 -> 三大系统 -> 门派知识树”的层级关系。
知识点界面先做文件夹式树状列表，后续再升级为图形树状图。
```

## 3. 每一步的固定工作方式

每一步都按这个流程推进：

```text
1. 先说明这一关要解决什么问题
2. 再解释需要学的最小技术概念
3. 然后写最少量代码
4. 运行项目看结果
5. 修正错误
6. 在计划书或进度文档里记录完成情况
```
